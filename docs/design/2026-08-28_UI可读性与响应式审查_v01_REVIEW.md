## 结论

修订后的界面达到工业工作台 Demo 的交付基线。原截图中的问题不是“审美偏好”，而是明确的可读性与布局风险：辅助文字大量落在 10–12px，2560 宽屏形成信息孤岛，回放场景、按钮、倍速和样本读数使用单行 flex 挤压，768px 附近的表格与证据卡没有稳定降级方式。

本轮没有更换 Wuno 颜色、图标或信息架构，只重建了字号、间距、容器和响应式行为。

## 权威规范怎么转成这次改动

### 1. 字号

WCAG 2.2 不规定产品界面的默认字号，但要求文字可放大到 200% 后仍可使用。Carbon 的 productive typography 给出 14/18 与 16/22 的正文尺度，并建议产品组件使用稳定、非流式的字号层级。本项目选择正文 16px、辅助文字 14px，是基于工业监测中文可读性与用户明确反馈做的保守取值。

参考：

- [WCAG 2.2 · Resize text](https://www.w3.org/TR/WCAG22/#resize-text)
- [Carbon · Productive type](https://v10.carbondesignsystem.com/guidelines/typography/productive/)

### 2. 点击与触摸目标

WCAG 2.2 AA 的目标尺寸最低要求是 24×24 CSS px，增强级目标为 44×44；Fluent Web 也建议最小 44×44 的触摸目标。本项目统一将按钮、选择器、输入框、摘要和关键链接的最小高度设为 44px。

参考：

- [WCAG 2.2 · Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum)
- [Fluent 2 · Layout](https://fluent2.microsoft.design/layout)

### 3. 响应式与横向滚动

WCAG Reflow 要求普通内容在 320 CSS px 宽度下不需要双向滚动；数据表属于允许例外，但必须把横向滚动限制在表格容器内。本项目在 390px 验收页面级无横向溢出，表格保留 720px 最小内容宽度并显示“可横向滚动”提示。

参考：[W3C · Understanding Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 4. 间距与分组

Fluent 使用 4px spacing ramp，并强调通过 proximity 表达元素关系。本项目不另建新设计语言，以 8px 为主要节奏：字段内部 6–8px、同组 16px、模块 24px、页面主间距 24–48px。

## 具体修订

- `--font-body: 16px`、`--font-support: 14px`、`--touch-target: 44px`。
- 内容宽度从 1440px 放宽到 1680px，改善 2560px 屏幕上的信息孤岛。
- 演示引导的标签与选择器采用 `max-content + minmax(0, 620px)`；700px 以下改单列。
- 回放控制改为 grid：场景、开始、暂停、倍速、样本读数不再互相抢宽度。
- 系统状态桌面四列，1200px 两列，700px 单列。
- 证据卡在 767px 以下变为“说明 + 数值 / 趋势独占下一行”。
- 移动表格只在自己的容器横向滚动，并给出文字提示。
- 顶部数据来源、登录状态在 1024 / 768 / 390 下按优先级隐藏或收敛，不与标题重叠。

## Playwright 验收

- 真实本地 API 创建 run 与 event，班长账号登录后提交人工决策并读取真实审计记录。
- 页面截图 8 张：演示引导、运营总览、过程回放、事件队列、事件研判、操作员登录、审计记录、系统状态。
- 响应式检查：5 个页面 × 4 个视口，共 20 项；页面级横向溢出均为 0。
- QA 记录位于中央产品手册工程的 `build/qa/playwright_截图与响应式验收.json`。

## 剩余风险

- 本轮没有逐个视口截取“已登录后的事件研判表单”，但 DOM、认证、测试和真实提交链路均已验证。
- 数据表在移动端仍需要局部横向滚动；这是多列工业数据的受控例外，不是页面级溢出。
- 部分后端场景名称仍为英文。它不影响布局，但正式中文交付应增加业务名称映射。
