## 1. 结论

序安的 AI 不是一个单独聊天框，而是贯穿“发现、解释、追问、人工编辑、影子门禁、决策、审计、运维”的受控链路。本地真实 Compose 环境和公网 HTTPS 环境均完成 UJ-09 至 UJ-11，并作为完整 11 条 Playwright 用户旅程的一部分通过；AI 专项没有跳过、重试或 flaky。当前公网复用 SSOS 的配置管理模式与路由口径，通过受控配置接入自有 OpenAI-compatible 服务 `https://ai.finlaw.cloud/v1`，实际模型为 `gpt-5.5`。

AI 专项共保留 5 个关键页面状态，每个状态同时保存首屏和完整页面；两套环境合计 20 张 AI 专项截图。API 字段级断言记录在同一 Playwright 结果与旅程清单中。

## 3. UJ-09：同一条 AI 证据链

### 3.1 工业模型输入与输出

- 从在线创建的 run 获取真实事件，不使用静态 `demo-event`。
- 事件模型版本必须匹配 `tep-pca-hgb-*`。
- 至少返回一个故障候选，并固定返回三项过程变量证据。
- 建议的安全边界必须精确为 `Read-only advice. No automatic control write-back.`。

### 3.2 人工追问

中控操作员使用演示账号登录后发出一个带本轮唯一时间戳的问题。后端回答必须满足：

- `answer` 非空；
- `mode` 只能是 `llm_enhanced`、`template` 或 `degraded`；
- `model` 和 `traceId` 非空；
- `latencyMs >= 0`；
- 至少引用一个证据变量，且每个 `evidenceRef` 都属于当前事件 Top-3 变量。

页面同时显示中文模式名称、模型、证据和 Trace，操作者能够看见这次回答究竟来自在线增强还是模板/降级路径。

### 3.3 调用审计

管理员读取 `/api/v1/admin/ai/interactions` 后，用唯一问题定位调用记录。记录中的 `eventId`、问题、答案、模式、模型、证据引用和 Trace 必须与刚才的回答逐字段一致。后台页面再用该 Trace ID 定位唯一一行，避免只凭相似文本误判。

## 4. UJ-10：AI 运维与安全边界

### 4.1 状态透明

- 总推理模式为 `online`；
- Worker 和工业模型必须为 `ready`；
- 工业模型版本必须匹配 `tep-pca-hgb-*`；
- 语言模型可以为就绪、降级、离线或未知，但非就绪时必须返回原因；
- 数据构建哈希不得为空。

这一区分很重要：工业模型在线并不等于语言模型一定在线。语言模型未启用时，偏移检测仍可工作，问答明确标记为模板或降级。

当前公网实测中，连接探针与事件追问返回 `llm_enhanced / gpt-5.5`；回答引用当前事件的 `XMEAS(33)`、`XMEAS(38)`、`XMEAS(29)`，带非零延迟和独立 Trace。配置版本为 4，Prompt 版本为 `event-copilot-v03-finlaw`。该证据证明真实调用链已接通，但不把单次成功扩大为持续可用承诺。

### 4.2 密钥不回显

管理员配置响应必须包含 Provider、Base URL、模型、超时、Token 上限、Temperature、Prompt 版本、降级策略、配置版本和 `apiKeyConfigured=true`。这个布尔值只证明服务端已安全配置密钥；响应不得出现 `apiKey`，页面密码输入框加载后必须为空，也不得在调用记录或审计详情中显示密钥值。

### 4.3 Demo 只读

公开部署对以下请求均由后端返回 `403 admin_ai_read_only`：

- `PUT /api/v1/admin/ai/config`
- `POST /api/v1/admin/ai/test`

这里关闭的是管理员手动发起的 `POST /admin/ai/test`，不代表运行时语言模型不可用。当前已配置的运行探针与事件问答均已真实返回 `llm_enhanced / gpt-5.5`；公网仅禁止用户修改配置或额外触发测试调用，避免未授权出站和额外配额消耗。私有部署可由运维显式开启写入，再结合白名单与出站策略使用。

## 5. UJ-11：AI 建议、人工编辑与影子门禁

操作员的新问题必须产生一条新的 AI 回答；自动化先比较回答数量，再读取最后一条回答的 `traceId`，避免误用页面中旧 Trace。操作员可以修改拟议动作，但不能绕过后端门禁。

提交后，后端创建并持久化控制提案。字段级验收要求：

- `sourceTraceId` 等于刚产生的 AI 回答 Trace；
- `proposedAction` 等于人工编辑后的文本；
- 恰有 5 项门禁，2 项通过、3 项阻断；
- `executionMode=shadow`；
- `state=blocked_demo_boundary`；
- `sent=false`；
- 页面与 API 都明确没有向 PLC、DCS、APC 或 SIS 发送指令。

这不是“已经接入控制系统”，而是把未来写回前必须经过的人、权限、工艺联锁、网关和二次确认变成可演示、可审计的软件路径。

## 6. AI 与人的责任分界

- AI 负责：发现偏移、组织候选、指出关键变量、解释原因、给出检查与处置建议、保留调用证据。
- 人负责：判断是否采纳、编辑动作草案、确认/驳回/升级、填写说明、承担生产决策责任。
- Demo 不做：自动写回 APC、DCS、PLC 或 SIS。
- 生产路线：建议草案 → 约束校验 → 权限与双人确认 → 受控网关下发 → 控制系统读回 → 效果评价与回滚。任何一步不满足都不得执行。
