# 三分钟 Demo 脚本

状态：`DRAFT`

## 0:00–0:20｜把问题说窄

“我们没有做一个泛化的智慧工厂大屏。我们只解决当班工程师看到异常后的十分钟：它是不是真偏了、先看哪三个变量、下一步先查什么、谁确认过。”

打开 `/demo`，指出页面顶部两条边界：`公开仿真数据`、`只读建议 / 不写回控制系统`。

## 0:20–0:55｜选择并开始回放

选择 `Fault 01 · A/C Feed Ratio Step`，点击开始回放。

“这是 Tennessee Eastman Process 的公开过程仿真。每三分钟一个样本，共 52 路变量。故障在样本 160 进入；系统用过去 20 个点形成一个 60 分钟窗口。”

让回放推进到偏移前后；不要在这一段切页面。

## 0:55–1:25｜异常被看见

异常出现后停住：

“这里不是单点越线就报警。T² 和 Q/SPE 连续越界后才形成事件。52 路变量先压成热力格，让人看见异常集中在哪一组；原始值仍可展开。”

指出数据新鲜度、异常时间窗和风险横幅。

## 1:25–2:05｜把模型判断变成证据

进入事件详情 `/events/{id}`：

“事件在样本 160 被检测并锁定，但此时分类器可以诚实地显示‘正常 / 尚未收敛’。系统不偷看测试集答案，而是在预先固定的 20 个样本后刷新候选与证据。这里的‘已更新’不是‘故障已确认’，最后仍由人判断。”

指出两阶段时间轴：`检测样本 → 固定延迟 20 点 → 研判样本`。再看候选、共享横轴的 Top-3 趋势、SPE 变量贡献和检查建议。对 F01 场景，初始候选未收敛，样本 180 刷新为 F01。

强调建议由模板也能生成：

“没有大模型密钥也能完整运行。大模型只负责把已经选定的证据改写得更易读，不参与阈值和控制决策。”

## 2:05–2:35｜人工确认与留痕

选择处置结论，补一句备注，提交人工确认。

“系统不会写回 DCS 或 PLC。工程师确认后，事件、证据、建议、处置人和时间进入审计记录，交班时可以复盘。”

打开 `/records/{id}` 展示只读记录。

## 2:35–3:00｜讲清上线第一步

“真上线的第一步不是买一套更大的模型，而是接一条历史数据链路，在一套装置上跑只读影子模式。先对齐变量字典和正常基线，再由工艺工程师校验检查顺序，连续 4–8 周评估提前量、误报、漏报和处置时间。我们今天交付的是这条 PoC 路径的可运行基座。”

停在审计记录或系统状态页，不在最后 10 秒切换新功能。

## 现场兜底

- API 网络不可达：前端只对浏览器网络错误切换到内置数据，并明确显示 `演示回退模式`；HTTP 4xx/5xx 不伪装成功，而是展示错误与重试。
- LLM 不可用：使用确定性建议模板。
- 公网入口未放行：使用 `ssh -N -L 127.0.0.1:18091:127.0.0.1:18090 wunoos`，再打开 `http://127.0.0.1:18091/demo`。
- 回放卡住：刷新 `/demo`，选同一场景重新开始；不要现场改代码。
