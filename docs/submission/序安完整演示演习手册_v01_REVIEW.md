# 序安 Process Sentinel 完整演示演习手册 v01

状态：`REVIEW`

公网入口：<https://huagong.finlaw.cloud/demo>

适用：黑客松评审、产业方演示、PoC 前沟通

主链路：管理预检 → 过程回放 → 偏移事件 → AI 追问 → 人工编辑 → 影子门禁 → 人工决策 → 审计留痕

## 1. 演示必须讲清的事实

- 当前数据是 Tennessee Eastman Process（TEP）公开化工过程仿真数据，不是贵州真实工厂数据。
- PCA / HGB 工业模型由 Worker 按样本在线推理；结果不是页面上预先写死的红灯。
- 语言模型是事件解释增强层。当前公网复用 SSOS 的配置管理模式，通过受控配置接入 OpenAI-compatible DeepSeek；实际模型为 `deepseek-v4-flash`，真实成功调用显示“在线增强”，单次失败必须明确显示“模板降级”，不能伪装成功。
- 管理后台包含运行概览、AI 配置、调用记录和配置审计。公网可查看，危险配置写入与连接测试默认禁用。
- 当前 Demo 只读，不向 APC、DCS、PLC 或联锁系统写回。
- 未来可做受控写回，但必须经过人工发起、权限校验、工艺上下限、联锁校验、人工二次确认、受控网关和失败回滚。

- 主演示人：讲问题、控鼠标、发起追问、提交人工结论。
- 演示助手：提前登录、记录新 run URL、监看 Worker / API / SSE，不在主演示时抢操作。

## 4. 演示前 10 分钟预检

### 4.1 公网与界面

- [ ] 打开 `/demo`、`/replay`、`/system`，页面无水平溢出、无组件重叠。
- [ ] 使用 `system-admin` 登录，能进入 `/admin`。
- [ ] `/admin` 显示 Worker 就绪、工业模型 `tep-pca-hgb-*` 就绪，并能看到实际模型版本。
- [ ] 语言模型显示 `deepseek-v4-flash / 在线增强`，并在现场新建事件追问得到“在线增强”；若临时降级，原因清楚可见。
- [ ] `/admin/ai` 能读取配置，API 明确返回 `apiKeyConfigured=true`，但密钥不回显且输入框为空。公网不执行保存或管理员手动连接测试；这不影响已配置的运行探针和事件问答完成真实调用。

### 4.2 真实回放

- [ ] 选择“进料组成阶跃偏移（故障 1）”并点“开始回放”。
- [ ] 回放创建后设为 `20×`，当前样本从 0 持续增长。
- [ ] 页面出现当前 run 的“进入事件研判”链接。
- [ ] 记下 run ID 和 event ID；刷新后仍能通过 URL 打开。

### 4.3 人机交互与留痕

- [ ] 在事件页追问“为什么不是传感器故障？”。
- [ ] 回答显示模式、模型、证据变量和 Trace ID。
- [ ] 切换班长或工艺工程师账号，提交一次“确认 / 驳回 / 升级”和研判说明。
- [ ] 打开事件记录，核对操作者、结论、模型版本、Trace ID 和时间线。
- [ ] 再使用管理员登录，在 `/admin/interactions` 找到本次追问。
- [ ] 用该次回答的 Trace ID 定位唯一调用行；问题、模式、模型和证据引用与事件页一致。
- [ ] `/admin/ai` 的 API 密钥输入框为空；页面和响应均不回显密钥值。
- [ ] 编辑 AI 拟议动作并运行影子门禁；确认 5 项门禁显示 2 项通过、3 项阻断，且 `sent=false`。

## 6. 故障演练

### 语言模型不可用

- 动作：继续走工业模型主链路，指出“模板降级”标签。
- 口径：“事件检测和证据仍来自在线工业模型；当前语言层使用确定性模板降级，没有伪装成在线大模型。”

### 回放样本不推进

- 动作：停止继续点页面；检查 `/admin` 的 Worker 状态、run 状态和 SSE；必要时新建 run。
- 禁止：不用旧事件冒充当前 run，不声称“其实后台在跑”。

### SSE 中断

- 动作：不要硬刷新页面；等待客户端自动重连，并观察它携带最后消息游标继续订阅。若自动重连失败，再新建 run。
- 验收：页面保留当前 run，不重复产生同一样本的事件，当前样本继续增长。

### 公网不稳定

- 动作：转入已预检的本地 Compose 环境，仍从新 run 开始。
- 口径：明确说“当前为本地同版应用”，不假装公网没有故障。

## 7. AI 完整流程现场验收

这部分不是可选讲解。现场至少要让一名操作员和一名管理员完成以下闭环：

1. 从新 run 产生在线事件，确认模型版本、候选原因和三项关键变量证据。
2. 操作员主动提出一个可被证据检验的问题，例如“为什么不是传感器故障？”。
3. 现场念出回答模式：`语言模型增强`、`模板降级` 或`服务降级`，不混用口径。
4. 指出模型名、证据变量和 Trace ID，说明 AI 给出的是建议与原因，不是最终生产结论。
5. 由有权限角色提交确认、驳回或升级；操作员账号只能升级。
6. 管理员在调用记录中按同一个 Trace ID 找到唯一记录，核对问题、模式、模型和证据。
7. 管理概览分别说明 Worker、工业模型和语言模型状态；指出 `deepseek-v4-flash` 的最近真实探测状态，降级时讲明原因。
8. 打开 AI 配置，确认 Provider、Base URL、模型和 Prompt 版本按 SSOS 的配置管理模式与路由口径适配，`apiKeyConfigured=true` 但密钥不回显；公网不保存配置、不触发管理员手动连接测试，已配置的运行探针和事件问答仍真实调用 DeepSeek（deepseek-v4-flash），配置版本为 5、Prompt 版本为 `event-copilot-v03-finlaw`。
9. 编辑拟议动作并运行影子门禁，现场说明 5 项中 2 项通过、3 项阻断，状态为 `shadow / blocked_demo_boundary / sent=false`；不把影子评估说成已经接入 PLC / DCS。

自动化证据见 `docs/submission/序安AI用户流程验收_v01_REVIEW.md`。本地与公网 UJ-09 至 UJ-11 均已作为 11 条完整旅程的一部分通过。
