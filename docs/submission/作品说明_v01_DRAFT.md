# 作品说明：连续化工过程偏移副驾驶

状态：`DRAFT`  
方向：`AI × 先进制造 / 连续化工过程异常研判`

## 我们锁定的问题

中控室当班工程师真正缺的不是又一个“红灯报警”，而是报警出现后的一条短路径：异常是否持续、最可能是什么、先看哪三个变量、应该先做什么、谁确认过。

本作品把命题缩到一个具体动作：**异常出现后，帮助当班工程师在一个页面内完成一次有证据、有边界、可追溯的研判。**

## Demo 主链路

`公开过程数据回放 → 偏移发现 → 候选故障 → Top-3 变量证据 → 处置建议 → 人工确认 → 审计记录`

- 52 路过程变量不叠成“意大利面图”，先用热力格发现异常变量组。
- 以 20 个采样点（60 分钟）为窗口，使用 PCA 的 Hotelling T² 与 Q/SPE 判断过程是否偏离正常基线。
- 以 HistGradientBoosting 生成候选故障排序；Top-3 贡献变量解释当前判断。
- 建议默认由确定性模板生成；即使没有大模型密钥，现场 Demo 仍可完整运行。
- 系统只读，不写回 DCS/PLC。处置动作必须由人确认并留痕。

## 数据与可信边界

Demo 使用 Tennessee Eastman Process 公开仿真数据，不宣称它等同于贵州磷化工企业的真实生产数据。上游仓库包含正常工况及 21 类故障的训练/测试文件；每个样本含 41 个测量变量和 11 个操纵变量。

## 为什么它有落地可能

上线第一步不是接管控制，而是选一套装置、一条已存在的历史数据链路和一个班组，把系统接成只读影子模式：

1. 对齐 DCS/时序库变量字典与采样时间。
2. 用历史正常工况建立装置自己的基线与阈值。
3. 由工艺工程师确认故障标签、检查顺序和安全边界。
4. 连续运行 4–8 周，只评估提前量、误报、漏报和处置时间，不做自动写回。

当前仓库给出了这条 PoC 路径所需的数据 manifest、模型版本、API 契约、前后端、容器部署与回滚脚本。

## 评委现场看什么

- 异常前后变化是否能在回放中清楚看见。
- 每个判断是否能落到候选故障、变量证据和明确检查动作。
- 断网、没有 LLM、API 暂时不可用时，主链路是否仍能演完。
- 是否明确展示“公开仿真数据”“只读建议”“人工确认”“不写回控制系统”。
