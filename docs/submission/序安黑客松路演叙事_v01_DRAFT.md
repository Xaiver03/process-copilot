# 序安 Process Sentinel 黑客松路演叙事 v01

状态：`DRAFT`  
受众：黑客松评委、制造业技术与业务决策者  
演示目标：让评委相信序安已经把“异常出现后的证据研判”做成可运行、可复现、边界诚实的产品基座，并值得进入真实装置的只读 PoC。

## 10 页叙事

1. **事故之前，过程先偏了一点**  
   序安 Process Sentinel 聚焦连续化工异常出现后的十分钟：系统先看见偏移，把关键证据交给工程师，人做最后判断。

2. **现场堵点不是没有报警，而是 52 路变量同时在说不同的话**  
   当进料组成、流量、压力、温度、阀位出现联动变化时，单点报警难以回答“是不是真偏了、先查哪里、谁确认过”。

3. **在事故形成前，把持续偏移从噪声里拎出来**  
   T² 与 Q/SPE 识别偏离正常基线的持续变化，热力格先压缩 52 路变量，再保留原始值和时间窗供工程师展开。

4. **AI 不只给结论，还给候选、Top-3 变量和检查顺序**  
   事件在首次持续越界点锁定；候选与证据按预注册的 20 个样本（60 分钟）刷新。`已更新` 不等于 `已确认`。

5. **主动交互不是聊天，而是推动一次可追溯的人机确认**  
   系统围绕事件主动组织风险、证据和建议；工程师选择结论、补充备注并确认，事件、证据、处置人和时间进入审计记录。

6. **产业已经证明闭环优化有价值，序安补的是安全异常研判层**  
   贵州省大数据发展管理局公开的贵州磷化集团“1468”案例，聚焦能耗、品质与设备预测，并通过 APC、RTO 与边缘控制实现参数优化闭环；其公开口径包括相关装置能耗降低 2% 以上、操作频次下降 70% 以上、稳定性提升 30% 以上。序安不复制这条定位，而是聚焦偏移提前发现、故障候选、变量证据、人机接管与审计。当前 Demo 只读；未来接入 APC/PLC/DCS 前，必须通过人工授权、权限校验、联锁/安全边界校验和受控控制网关。

7. **公开数据、冻结构建、版本化模型，让每次判断可复现**  
   使用 Tennessee Eastman Process 公开仿真数据；保留上游来源、ZIP SHA-256、buildHash、模型版本和冻结场景。它不代表真实贵州工厂生产数据。

8. **三分钟现场 Demo，从回放走到审计记录**  
   选择 F01 场景 → 开始回放 → 看见偏移 → 打开事件研判 → 查看 Top-3 证据 → 人工确认 → 展示审计记录；网络或大模型不可用均有诚实降级。

9. **落地从一套装置的 4–8 周只读影子模式开始**  
   对齐变量字典和采样时间，用历史正常工况建立基线，由工艺工程师校验检查顺序；连续评估提前量、误报、漏报和处置时间，不做自动写回。

10. **下一步：用一个班组，把判断时间变成可验证的工程指标**  
    选择一套装置、一条历史数据链路和一个班组，定义 PoC 验收口径；序安交付数据 manifest、模型版本、API 契约、前后端、容器部署与回滚基座。

## 事实与措辞边界

- 不使用企业真实产量、收益、事故率、提前量或误报率等未提供数据。
- 不把 TEP 仿真结果描述为真实装置效果。
- 不声称当前系统具备 DCS、PLC、联锁或控制回路写回能力。
- “人机主动交互”限定为事件驱动的证据组织、检查建议、人工确认与审计留痕，不虚构当前不存在的自由对话能力。
- 未来写回仅作为路线图，并明确人工授权、权限校验、联锁/安全边界校验、控制网关与失败回退。
- 贵州磷化集团“1468”案例仅作为公开产业参照；不暗示序安与贵州磷化集团存在合作，也不暗示序安拥有其真实生产数据。
