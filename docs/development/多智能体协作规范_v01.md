# Codex 与 Claude Code 多智能体协作规范 v01

状态：`REVIEW`

## 1. 长期分工

- Codex 是总控：拆解任务、确定事实口径、分配写入边界、集成代码、运行验收、分组提交和推送。
- Claude Code 是受控外部智能体：优先承担边界清晰的代码阅读、资料检索、文案初稿、独立审阅，以及不会与其他智能体重叠的模块实现。
- Claude Code 的输出不是交付结论。Codex 必须复核变更范围、证据与测试后才能提交。

## 2. 何时启用 Claude Code

适合：

1. 只读梳理一个模块或验证一组事实。
2. 根据已有代码生成手册、测试清单或审阅报告初稿。
3. 对一个独立目录实施小功能，且写入集合可以提前锁定。
4. 需要第二视角做代码、安全或文档审阅。

不适合：

1. 多个智能体需要同时修改同一文件。
2. 最终合并、版本发布、主分支推送或历史改写。
3. 需要接触与任务无关的生产密钥、客户数据或个人信息。
4. 目标仍然含糊、无法定义验收证据的工作。

## 3. 每次派工必须提供

- 目标和完成定义。
- 已知事实、相关路径和关键符号。
- 允许读取与写入的范围。
- 明确禁止修改的文件和操作。
- 可执行的验证命令。
- 预期返回内容：提交 SHA、变更清单、测试结果或审阅结论。

## 4. 建议调用模板

只读任务默认使用无持久会话、限制工具和预算的命令：

```bash
claude -p \
  --model sonnet \
  --effort medium \
  --permission-mode plan \
  --tools Read,Grep,Glob \
  --max-budget-usd 0.80 \
  --no-session-persistence \
  '在指定路径内完成只读核验；返回事实、证据路径、风险和最小下一步。'
```

实现任务必须额外限定独立 worktree、写入目录和测试命令；Claude Code 不得自行推送 `main`。

## 5. 集成门槛

1. 检查 `git status` 与 diff，排除越界文件。
2. 运行与风险匹配的测试、构建和视觉 QA。
3. 对密钥、网络请求、权限、迁移和并发改动做专项复核。
4. 一步一提交，提交信息说明单一职责。
5. 由 Codex 非强制推送并核对远端 SHA。

本规范的目标是减少重复推理和主会话消耗，不以降低验收质量、扩大权限或隐藏风险为代价。
