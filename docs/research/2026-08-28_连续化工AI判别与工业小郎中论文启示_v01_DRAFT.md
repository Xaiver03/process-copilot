# 连续化工过程 AI 判别与“工业小郎中”论文启示

状态：`DRAFT`<br>
版本：`v01`<br>
日期：`2026-08-28`

## 一句话结论

连续化工监测不应被实现成“模型看见一行数据，直接报一个故障名”。可信的 AI 判别至少要依次完成：**数据与工况有效性判断、异常检测、故障隔离、故障分类或未知拒识、严重度评估、证据融合、人工闭环**。

本项目当前适合作为一条可演示的离线基线：PCA T²/SPE 负责发现偏移，窗口分类器给出三类候选，SPE 贡献度解释 Top-3 变量。下一步最值得做的不是堆大模型，而是把它升级为**按工况建模的在线混合诊断器**，并用误报率、漏报率、检测延迟和未知故障拒识能力验收。

## 1. 先把“AI 判别”拆开

| 层级 | 要回答的问题 | 建议输出 | 不应混淆 |
|---|---|---|---|
| 数据质量 | 这批数据能不能信？ | 缺失、冻结、漂移、越界、时间错位 | 传感器坏不等于工艺异常 |
| 工况识别 | 当前处于哪种正常模式？ | 稳态、开停车、负荷切换、配方/原料切换 | 正常切换不等于故障 |
| 异常检测 | 是否偏离该工况的正常空间？ | T²、SPE、物料/能量平衡残差、持续时间 | 异常不等于已知故障 |
| 故障隔离 | 最先偏的是哪里？ | 变量贡献、设备/回路、传播路径 | 相关变量不等于根因 |
| 故障分类 | 像哪个已知故障？ | Top-K 概率、置信度、相似案例 | 低置信度不能强行归类 |
| 未知拒识 | 是否超出已知故障集合？ | unknown / novel、距离或能量分数 | 不应把未知故障包装成最高概率类别 |
| 严重度与趋势 | 还在发展吗？ | 速度、持续性、影响范围、风险等级 | 单点峰值不等于持续恶化 |
| 决策支持 | 先查什么、谁确认？ | 证据、建议、禁忌、人工确认和审计 | 系统不写回 DCS/PLC/联锁 |

这组拆分与故障检测和诊断文献中的 detection、isolation、identification 等任务边界一致。异常事件管理的目标是尽早发现异常，同时避免模型越过控制和安全保护边界。

## 2. 当前项目实际上怎样判别

当前冻结模型 `tep-pca-hgb-5bc36d3f4e6b` 使用 Tennessee Eastman Process（TEP）公开仿真数据：41 个测量变量 `XMEAS` 与 11 个操纵变量 `XMV`。主链路是：

```text
TEP 冻结回放
  -> StandardScaler（仅在正常训练数据拟合）
  -> PCA（累计解释方差 95%）
  -> T² / SPE，正常训练分布 99% 分位数作阈值
  -> max(T²/T²阈值, SPE/SPE阈值) >= 1 触发异常
  -> 20 样本窗口特征：末值、均值、标准差、变化量、斜率
  -> HistGradientBoosting 给出 F01 / F06 / F13 候选
  -> SPE 重构残差贡献给出 Top-3 变量
  -> 确定性安全建议模板
  -> 人工确认与审计记录
```

按当前 180 秒采样间隔，20 个样本相当于约 60 分钟。系统用首次超阈值样本锁定事件，20 个样本后刷新候选与证据；“已更新”不等于“已确认”。

### 当前能力边界

- 产物是在构建阶段离线生成的冻结事件模板，API 负责回放，不是对实时 DCS 数据持续推理。
- 分类器只覆盖正常类和 F01、F06、F13 三种 Demo 故障，不能代表 TEP 全故障，更不能代表真实磷化工装置。
- 当前阈值没有按开停车、负荷、配方或季节工况分层，真实现场容易把模式切换报成异常。
- T²/SPE 和 Top-3 贡献度能说明“偏离了什么”，不能单独证明根因。
- 公开仿真数据不能支持生产误报率、漏报率、提前量、经济收益或安全收益声明。

因此，当前作品说明应使用“**公开仿真上的可复现判别链路**”，不能使用“已实现现场预测性维护”或“可提前多少分钟预警”。

## 3. “工业小郎中”论文提供了什么证据

论文《磷化工设备专用智能诊断服务平台“工业小郎中”应用实践》报道：平台自 2024 年 6 月起分两期部署于 7 个生产装置现场，使用 1000 余只无线振动温度传感器覆盖 400 余台关键设备，进行 7×24 小时监测。传感器在轴承座采集水平、垂直、轴向振动与温度，经网关、边缘特征提取和 4G/5G 上传云端。

它的诊断链路值得直接借鉴：

```text
多轴振动/温度
  -> 边缘特征提取与压缩
  -> 机理模型：转子动力学、轴承特征频率
  -> 机器学习：历史案例中的波形/频谱模式
  -> 贝叶斯推理融合
  -> 故障类型、维护建议
  -> APP / Web / 邮件
  -> 现场点检、拆检、维修结果回填
  -> 案例与模型优化
```

论文给出的六个月统计窗口为 2024-12-01 至 2025-05-31：共预警 21 起严重故障，并称均由拆检或维修专家确认。故障分布为轴承故障 11 起（52.4%）、联轴器磨损 4 起（19.0%）、叶轮结垢不平衡 3 起（14.3%），其余类型各 1 起；前三类合计 85.7%。

P-404A2 案例呈现了完整的闭环：SKF 6315 轴承内圈异常从 1 月 3 日早中期损伤预警、1 月 10 日进展并生成缺陷工单，到现场听诊和手持仪器确认、带病受控运行、3 月 26 日临停拆检确认、换密封和轴承，再到 3 月 31 日平台恢复正常并闭环缺陷。

### 证据边界

论文没有提供误报总数、漏报总数、按设备小时计算的误报率、召回率、提前量分布、对照组、原始数据、模型参数或置信度校准。因此：

- “21 起均被确认”只能描述论文报告的已确认事件，不能据此推出 100% 准确率或 100% 召回率。
- 旋转设备的高频振动/频谱诊断与 DCS 低频、多变量、强耦合过程监测不是同一个建模问题。
- 可以迁移的是“机理 + 数据模型 + 概率融合 + 人工闭环”的架构，不能直接搬用轴承故障模型。

## 4. 面向连续过程的目标判别架构

```text
DCS / Historian / 设备振动 / 实验室化验 / 工单
            |
            v
  [L0 数据可信度与时间对齐]
  缺失、冻结、坏点、漂移、采样周期、传感器健康
            |
            v
  [L1 工况识别与正常模型路由]
  稳态 / 开停车 / 负荷 / 配方 / 原料批次
            |
            v
  [L2 多证据异常检测]
  DPCA/CVA T²/SPE + EWMA/CUSUM + 物料/能量平衡残差
            |
            v
  [L3 诊断与未知拒识]
  时序表征 + 已知故障分类 + open-set unknown
            |
            v
  [L4 传播解释]
  P&ID/因果图 + 时滞 + 变量贡献 + 相似历史案例
            |
            v
  [L5 概率融合与事件状态机]
  Bayesian / calibrated ensemble + 持续性 + 影响范围
            |
            v
  [L6 人机闭环]
  建议 -> 现场核验 -> 工单 -> 结果回填 -> 审批后离线更新
```

### L0：先判数据是否可信

每个点位至少维护：新鲜度、缺失率、冻结值、越界、变化率、与冗余测点一致性、维护状态。数据质量失败时输出“传感器/链路异常”，不进入工艺故障分类。所有变量按事件时间对齐，并保存原始值、清洗值和质量标记。

### L1：按工况选择正常空间

真实连续装置通常存在多个正常模式。先用生产计划、操作状态和无监督聚类识别模式，再为每个稳定模式拟合正常模型；开停车和切换阶段使用单独规则或模型。若工况置信度低，只发“模式未知/需人工确认”，避免用稳态阈值误判。

### L2：三类异常证据并行

1. **统计残差**：DPCA 或 CVA 处理时间相关性，输出 T²/SPE 及变量贡献。
2. **趋势证据**：EWMA/CUSUM 识别缓慢漂移，避免只靠单点阈值。
3. **机理残差**：物料衡算、能量衡算、反应器/换热器简化软测量模型，输出可解释的守恒偏差。

告警不应由单个采样点触发。建议采用“进入阈值 + 连续 K 次/时间窗占比 + 退出阈值”的滞回状态机，并针对不同模式分别标定。

### L3：已知分类与未知拒识同时存在

使用大量无标签历史正常数据做自监督时序表征，再用少量已确认工单训练分类头。输出必须包含 Top-K、校准概率和 unknown 分数。若最大概率不足、表征距离过大或多模型冲突，系统应输出“未识别偏移”，而不是强行选一个故障名。

### L4：解释传播路径，而不是只列相关变量

把 P&ID、控制回路、物流方向和已知时滞转成过程图。异常发生后同时检查：

- 哪个变量最早越界；
- 后续变量是否按工艺方向和合理时滞传播；
- Top-3 SPE 贡献是否与传播路径一致；
- 相似历史事件最终由哪项现场检查确认。

这能把“XMEAS(21) 贡献最高”翻译为“先检查哪个回路、阀门、换热面或原料条件”，同时明确它仍是候选根因。

### L5：融合时显式保留不确定性

可把四组证据统一到事件级概率：

```text
P(故障 | 证据) ∝
  P(统计残差 | 故障)
× P(机理残差 | 故障)
× P(时序分类 | 故障)
× P(传播路径一致 | 故障)
× P(故障先验 | 当前工况)
```

实际实现不要求第一版就做完整贝叶斯网络，但必须做概率校准、证据冲突标记和 unknown 兜底。用户界面应把“检测到异常”“候选已更新”“人工已确认”明确分开。

### L6：反馈是受控标签，不是自动真值

现场确认记录至少包括：核验人、时间、操作前后状态、检查项、拆检/化验结果、真实处置和结果。只有经过工艺或设备专家批准的记录才能进入训练集；驳回和无结论事件也要保留，以计算误报和选择偏差。模型更新采用离线审批、版本化发布和可回滚，不做在线自学习。

## 5. 验收指标必须按“事件”计算

| 指标 | 建议口径 | 为什么重要 |
|---|---|---|
| 误报率 | 每装置日/每设备月误报事件数 | 样本级准确率会被大量正常点稀释 |
| 事件召回率 | 已确认故障中，在处置前被发现的比例 | 回答漏掉了多少真实问题 |
| 检测延迟 | 故障注入/确认起点到首次有效告警的分布 | 回答是否真有提前量 |
| 事件精确率 | 告警事件中被现场确认的比例 | 衡量班组告警负担 |
| AUPRC | 针对类别不平衡的分类评估 | 比单看 accuracy 更可靠 |
| 校准度 | ECE / Brier score | 80% 置信度是否约有 80% 成立 |
| 未知拒识 | 未见故障 AUROC、FPR@TPR 或 OSCR | 防止未知故障被错误命名 |
| 告警抖动 | 同一事件重复开启/关闭次数 | 决定现场是否愿意使用 |
| 数据覆盖 | 有效点位率、有效工况时长 | 区分模型问题和数据问题 |

### 最小验证设计

- 按整段运行和时间切分训练/验证/测试，不能把相邻窗口随机打散。
- 留一个生产模式做 mode holdout，验证新工况下的保守降级。
- 留一类故障完全不参与训练，验证 unknown 拒识。
- 注入缺失、冻结、漂移、错时和通信中断，验证数据质量层不会误报工艺故障。
- 对慢漂移、突变、间歇故障分别报告检测延迟。
- 真实上线先做 4–8 周只读 shadow mode，不写控制系统；由班组确认事件并建立基线。

## 6. 可执行升级路线

### P0：保持当前 Demo 诚实可复现（现状）

- 保留 TEP 冻结场景、两阶段时间轴、人工确认和审计链路。
- 页面固定显示“公开仿真 / 离线冻结模型 / 不控制现场”。
- 现场演示只证明路径能跑，不宣称生产指标。

验收：同一版本、同一场景结果可复现；完整链路稳定通过。

### P1：在线判别基座（建议优先，2–3 周）

- 新增流式 telemetry 接口或 replay executor，逐采样推进而不是读取冻结事件模板。
- 实现数据质量状态、模式字段、DPCA/CVA 与 EWMA/CUSUM。
- 增加事件滞回、持续性、冷却期和重复事件合并。
- 将模型版本、阈值版本、变量字典和数据时间范围写入每条事件。

验收：在未读取故障真值的盲测回放中，实时产生事件；报告事件级误报、召回和延迟。

当前已完成 P1 的第一块可执行内核：`OnlinePCAMonitor` 可按连续样本索引运行数据质量门、PCA T²/SPE 评分、Top-N 贡献变量、持续性进入和滞回退出状态机；`evaluate_alarm_episodes` 使用全局一对一匹配计算事件级 precision、recall、检测延迟、重复告警和误报事件率。候选起点与真正开事件样本已明确区分，坏数据、样本缺口、不可解析值和过早告警不会被静默算成命中。冻结 Demo 盲测中，F01 与 F13 被检出；F06 告警早于标注起点 10 个样本且持续不退，严格口径下计为误报加漏报。它目前仍是纯 Python 领域内核，尚未接入 API worker，也未包含工况路由、DPCA/CVA 或 unknown 拒识。运行方式、完整基线和边界见 `services/ml/README.md`。

### P2：诊断与未知拒识（3–4 周）

- 对无标签历史窗口训练自监督时序编码器。
- 用已确认故障训练分类头并做温度缩放或等距回归校准。
- 引入 open-set 阈值和“未识别偏移”状态。
- 与 PCA/DPCA 基线在相同切分上比较，不以复杂度代替收益。

验收：故障留一类测试中能拒识未知；校准误差和事件级精确率达到预注册门槛。

### P3：机理、传播与工单闭环（4–8 周）

- 从一套装置、一个单元开始整理 P&ID 图谱、关键守恒式和时滞。
- 融合统计残差、机理残差、时序分类和图传播一致性。
- 接入只读 Historian 与工单结果，形成专家审批标签。
- 建立模型卡、数据卡、版本审批、回滚和漂移监控。

验收：一个明确单元完成 shadow mode；班组能从告警进入核验、反馈和复盘，不需要模型写回控制系统。

## 7. 黑客松 Demo 应怎样讲

建议把问题缩到一个动作：

> 当反应段出现持续偏移时，让当班工程师在一分钟内看见“偏移是否持续、最先影响哪三个变量、最像哪类已知故障、证据是否互相支持、下一步先查什么”，并把确认结果留下来。

三分钟主链路：

1. 选择 F13 慢漂移场景并开始回放。
2. 首次异常出现时，只显示“检测到偏移”，不立即冒充确诊。
3. 经过预注册窗口后刷新候选、Top-3 变量与安全建议。
4. 展示“已知候选置信不足时应进入 unknown”的下一版设计。
5. 工程师确认/驳回，生成审计记录。
6. 明确说明上线第一步：接一套装置的只读历史数据，做 4–8 周 shadow mode 并测事件级误报和提前量。

## 9. 当前决策

1. 保留 PCA T²/SPE，作为可解释、可复现、低成本的第一基线。
