## 一、审计目的与总口径

本审计用于约束项目介绍、Demo 讲解、接口说明和后续 Codex 生成内容的事实边界。项目的一句话口径是：

> 基于 DCS 时序数据，提前预测工业过程风险，给出原因证据和处置建议，并由人确认闭环。

默认叙事场景为**污水出水风险预测**；**TEP 连续化工过程偏移**仅作为可切换的连续化工演示场景。两者都用于说明“时序数据—风险预判—证据解释—人工确认”的产品链路，不得混写成同一现场、同一数据集或同一验证结论。

用户已确认：现场 DCS 已有接口。AI 的核心价值不是再造采集系统，而是把已有在线变量与滞后的离线化验标签对齐，提前预测未来化验周期的出水风险。当前 Demo 为只读/影子建议，`sent=false`；生产写回只是未来受控路线，不是当前能力。

## 二、已核实公开事实

### 1. 公开数据与来源

- 公开 UCI Water Treatment Plant 官方描述为 **527 个日记录、38 个变量**，数据于 **1993 年捐赠**，许可为 **CC BY 4.0**。
- 本地镜像实际仅有 **520 条非空记录**，并含缺失值。对外材料必须同时披露官方描述与本地镜像差异，不得把 520 条写成官方数据总量，也不得暗示本地镜像已完成无缺失清洗。
- Tennessee Eastman Process（TEP）是公开过程仿真基准，可用于连续化工过程偏移/故障研判演示；TEP 仿真不等于任何真实企业装置。
- 既有 TEP Demo 使用 41 个测量变量与 11 个操纵变量，采用 PCA T²/SPE、窗口特征、候选分类和变量贡献解释；当前结果属于公开仿真上的可复现链路。

### 2. 公开行业旁证与政策背景

- 部分同集团公开废水指标存在手工/月度监测旁证。该旁证只能说明存在公开的人工或周期性监测信息，不能证明已有实时 DCS 化验标签链路、连续在线仪表覆盖、模型效果或现场部署。
- HJ 1480-2026 将于 **2026-10-01** 实施，并强调重点监测点视频联网。此信息可作为环保监测数字化和联网趋势的政策背景；不能写成项目已满足该标准、已部署现场视频或已完成合规验收。
- 交椅山相关材料记载 HDPE 膜老化、雨污分流不足、排水沟堵塞/渗漏等风险。它们可作为环境风险叙事或待核查问题来源；不能写成当前客户现场已被平台识别、已被模型验证或已形成实测告警。
- 四川 DCS 规格与其他磷化工案例可作为行业参考，用于说明数据接口、控制系统和场景的可能形态；不能称为本项目当前客户现场参数、接口规格、部署规模或验证结果。

## 三、用户确认现场事实

以下内容可以作为项目当前现场前提，但仍不应扩展为未经确认的性能结论：

- 现场已有 DCS 接口，可作为接入既有在线过程变量的入口。
- 现场问题具有“在线变量较快、离线化验标签较滞后”的时间差；项目要做的是时间对齐和未来化验周期风险预测。
- 当前 Demo 是只读/影子建议，事件发送状态为 `sent=false`；系统不向 DCS、PLC、联锁或控制回路自动写回。
- 处置建议需要由人员确认，并形成可追溯的确认/驳回记录；生产写回需要另行进行安全审查、权限控制、审批和灰度验证。

现场仍需补齐的事实包括：实际变量字典、采样周期与时钟质量、化验项目和采样/出结果时间、历史标签覆盖、工况切分、排放口与监测点映射、班组处置流程、权限边界和安全审查结论。

## 四、产品推断与路线图

这些内容是基于已知事实形成的产品设计，不是当前现场实测事实：

### 1. 产品闭环

```text
DCS 在线变量
  -> 时间对齐与数据质量检查
  -> 预测未来化验周期的出水风险
  -> 输出风险等级、趋势、原因证据和待核查项
  -> 人员确认/驳回
  -> 形成审计记录与经批准的标签
```

默认污水场景中，平台应优先展示“未来一个化验周期是否存在出水风险”“哪些在线变量贡献较大”“还需要核对哪些工况或设备”。模型输出应被表述为风险预测或候选解释，而不是检测到已经超标的事实。

### 2. 双场景设计

- **默认场景：污水出水风险预测。** 以 DCS 在线变量和滞后离线化验标签为核心，强调时间对齐、未来周期预测、原因证据和人工闭环。当前不得填写真实准确率、提前量、ROI 或法律限值命中结论。
- **切换场景：TEP 连续化工过程偏移。** 用公开仿真回放展示 PCA T²/SPE、持续偏移、候选故障和 Top-3 变量证据。它是产品能力的可复现演示，不是污水现场数据，也不是磷化工真实装置参数。

### 3. 建议路线

1. 先以只读方式对齐 DCS、时序库和化验标签，建立数据质量与时间基线。
2. 使用历史数据进行离线回放和盲测，按事件级指标评估误报、漏报、检测延迟和告警负担。
3. 进入 4–8 周 shadow mode，由工艺人员确认事件、记录处置结果和驳回原因。
4. 在完成安全审查、权限设计、审批和可回滚验证后，再讨论受控写回；写回不是当前 Demo 的交付内容。

## 五、禁止表述

以下表述不得出现在项目介绍、路演稿、页面文案、API 说明或自动生成材料中：

- “已在真实客户现场稳定运行”“已接入现场生产并持续预测”——当前仅有 DCS 接口这一用户确认事实，Demo 为只读/影子建议。
- “已实现自动控制/自动调阀/自动联锁/自动写回 DCS”——当前 `sent=false`，生产写回只是未来受控路线。
- “准确率、召回率、提前量、误报率、ROI 已达到某数值”——当前没有足够现场验证数据支撑。
- “预测出水已经超标”“保证达标”“满足法律限值”——风险预测不能替代实测化验、监管判定或合规审查。
- “UCI 数据有 520 条记录且无缺失”——官方描述为 527 条日记录、38 变量；本地镜像为 520 条非空记录且含缺失。
- “TEP 数据就是磷化工/污水现场数据”“四川 DCS 规格就是本项目现场参数”——这些只能作为公开仿真或行业参考。
- “环评预测结果已被现场实测验证”“交椅山风险已被平台识别”——相关材料不能替代现场实测和项目验证。
- “已部署现场视频联网/在线传感器”或“已满足 HJ 1480-2026”——政策背景不等于本项目部署或合规结论。
- “AI 替代工程师作出处置决定”——平台提供证据和建议，最终确认与处置责任在人。
