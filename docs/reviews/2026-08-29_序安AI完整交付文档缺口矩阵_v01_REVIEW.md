## 3. 当前实现、Demo 限制、未来路线的固定分层

- **当前实现**：公开 TEP 数据回放；Worker/工业模型事件研判；事件证据与建议；语言模型增强或模板/降级回答；问答和配置审计持久化；RBAC 人工决策；控制提案影子门禁且永不发送。
- **Demo 限制**：预置账号；公开仿真数据而非贵州真实工厂；没有真实 DCS/PLC/APC/SIS 连接；没有真实工艺收益、误报率、漏报率、提前量结论；外部 LLM 可不可用取决于运行配置；浏览器网络回退不等于服务端在线。
- **未来路线**：真实装置变量字典/采样/工况/基线重对齐；连续只读影子运行 4–8 周；校准与 unknown/novel 拒识；企业 IAM 与职责分离；经安全审查的控制网关、上下限/联锁、双人确认、读回、回滚、效果评价；在全部门槛满足前不得写回。

## 4. 发布前文档验收条件

1. 产品手册、README、演习手册、AI 用户流程验收对 `UJ-11` 编号和状态保持一致；若未完成，明确写“未建立/未验收”。
2. 每个“在线 AI”词汇同时说明是语言模型探针成功还是 Demo 回放中的工业模型在线推理。
3. `template`、`degraded`、`offline`、`unknown` 分别落在回答模式或运行状态的正确语义层，不混用。
4. 截图路径、Playwright 测试名、journey manifest 和正文编号一一对应；不得引用尚不存在的 UJ-11 图。
5. 所有控制相关文案保留固定边界：`Read-only advice. No automatic control write-back.`；中文同时写明“不向 PLC/DCS/APC/SIS/联锁发送”。
6. 只有在真实部署、数据库持久化、权限、安全审查和回滚演练均完成后，才能把“未来路线”升级为生产能力描述。

## 5. 优先五项

1. **保持 UJ-11 为发布门禁**：本地与公网实跑、首屏/全页截图、manifest 和部署提交已经对齐；后续每次控制路径变更必须重跑。
2. **统一四种状态文案**：严格区分回答 `mode` 与管理端运行 `status`，尤其是 `offline/unknown/degraded`。
3. **补齐影子门禁持久化证据**：展示提案、5 项检查、Trace、`sent=false` 和控制网关关闭，避免“预演”被误读为写回。
4. **把问答、决策、影子提案串成同一 Trace 链**：在管理后台和记录页提供可复核截图与字段级断言。
5. **冻结当前/限制/未来三层发布话术**：所有产品手册、Demo 讲稿和评审口径都明确公开仿真、只读建议、人工确认和不写回边界。
