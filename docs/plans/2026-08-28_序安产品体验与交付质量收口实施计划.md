# 序安 Process Sentinel 产品体验与交付质量收口实施计划

> **For Codex:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task.

**Goal:** 在不修改模型训练和后端判别代码的前提下，完成用户可见品牌、AI 五步链路、四档响应式、截图资产、产品手册与公网部署的可复验证收闭环。

**Architecture:** 维持现有 Next.js、FastAPI 与模型契约不变，只在 Web 表现层、文档专用截图工具、中央 LaTeX 工程和验收记录中做最小收口。现有界面已具备五步 AI 主链路，因此不重做信息架构；新增精确品牌契约、截图产物显式分类、元素重叠检查和版本化 PDF，以自动化证据替代主观结论。

**Tech Stack:** Next.js 15、React 19、TypeScript、Vitest、Playwright、Node.js test runner、XeLaTeX、latexmk、Poppler。

---

## 方案选择

本轮比较过三种路径：一是重做界面，风险是破坏已通过的 39 项 Web 基线；二是只写验收报告，无法补齐重叠和截图分类的自动证据；三是保留现有设计、针对证据缺口做最小增强。采用第三种路径，因为它能保持产品行为和后端边界稳定，同时让品牌、布局、截图、PDF 和公网 smoke 都可重复验证。
