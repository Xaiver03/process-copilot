# 序安回放与人机闭环交互设计

## 目标

让评委在一条连续主链路中看见：过程数据推进、正常基线、故障注入、AI 发现异常、形成原因和建议、操作者主动追问与修改、人工确认，以及 Demo 只读条件下的控制写回预演。

## 当前问题与根因

- 点击“开始回放”只创建 run 并改变 `state`，前端没有时钟、轮询或遥测订阅，后端 worker 也不推进 `currentSample`。
- 热力图是固定完整图，播放前后没有区别，还提前展示未来数据。
- 低偏移颜色近似白色，正常基线看起来像空白；异常抬升从约样本 128 开始，与故障样本 160 不一致。
- 事件页用“AI 为什么这样判断”等说明性标题，没有让操作者提出问题、调整处置草案或预演下发。
- API 场景名直接显示英文；安全文案把“当前 Demo 不写回”误写成“产品没有写回能力”。

## 交互方案

### 1. 确定性 Demo 回放时钟

创建 run 后，从后端返回的当前样本开始推进；速度决定每个时钟周期增加的样本数。暂停后停止推进，重新播放继续。回放只负责展示，不反写服务端真实采样值。

### 2. 只展示已经发生的数据

热力图接收当前样本，只绘制当前样本之前的数据；未来区使用中性底色并标为“尚未回放”。样本 160 前显示可辨识的浅蓝正常波动，样本 160 处显示“故障注入”竖线，之后三项关键变量逐渐变为偏移和严重。

### 3. 可见的 AI 行动时间线

- 样本 0–159：AI 持续读取 52 路变量，显示“正常基线”。
- 样本 160–179：偏移锁定，显示异常分数与首次告警。
- 样本 180 起：候选刷新、证据对齐、建议生成，显示进入事件研判入口。

### 4. 人机主动交互

事件页加入基于当前事件证据的问答区。操作者可以输入问题或选择快捷问题；回答必须引用当前候选、贡献变量和风险，不声称调用了未接入的在线大模型。标题从“AI 为什么这样判断”改为“原因”。

### 5. Demo 与生产写回边界

当前 Demo 不连接控制网，不向 PLC/DCS 写回。界面提供可编辑的处置草案与“写回预演”，展示未来生产流程：人工确认 → 权限校验 → 联锁校验 → 控制网关 → PLC/DCS。预演只生成拟下发内容并明确“未发送”。

### 6. 中文展示层

按 `faultId` 翻译场景名称和说明；变量编号、PLC/DCS/PCA 等保留，其他可见文字使用中文。底层 API 原值不改，避免破坏数据溯源。

## 验收标准

- 点击播放后 1 秒内，当前样本、进度和至少三项遥测值可见变化。
- 暂停后样本停止，继续播放后恢复。
- 异常提示只在到达事件样本后出现。
- 热力图正常区可见、未来区不泄露、故障注入点与样本 160 对齐。
- 事件页存在可输入的人机问答并返回基于事件证据的回答。
- “原因”替代“AI 为什么这样判断”；场景和主要说明中文化。
- 当前 Demo 明确不写回，同时展示生产写回的受控路径。
- Logo 在 24px 尺寸可识别，页面无重叠和水平溢出。
